# 交互海洋：诊断与实施边界

## 现有问题

审查基于铁轨修复后的 `2240e4f`。现有 OceanWater 已在顶点 Shader 中执行三组 Gerstner 的水平/垂直位移，64×32 网格及八项控制确实生效，时间使用积分相位，不是滚动纹理冒充几何。默认总振幅 .067、单波权重分摊后很低；弱高光、透明混合和粗网格使轮廓不明显。细涟漪只扰动法线。没有局部扰动源、二维传播状态或鼠标水面映射，因此尚不具备交互水波。

水面、外侧壁、海床已分层，岸侧共面墙已去除。保留这项修复及深度测试。原岸线、建筑和道口不移动；铁轨修复与实体支撑检查继续保留。

## 实施方案

1. 加强基础波幅与材质反馈，增加有限网格细分；水平陡度单独限制，避免高度增大导致折叠。
2. 引入小型二维高度场，固定步长离散波动方程，阻尼、边界吸收、有限振幅。鼠标注入局部峰谷，停止后保持传播，不立即清空。基础波与交互高度相加，并一起重建法线。
3. 已检查 Three r180 GPUComputationRenderer 和官方 GPGPU 水例的双浮点纹理方案。当前约 4,600 格点，选择 CPU TypedArray 求解 + 单通道浮点 DataTexture 上传 + GPU 顶点采样：不依赖浮点渲染目标和浮点线性过滤，不增加计算渲染 pass，便于独立验证稳定性和阻尼。触屏降低格点与顶点数。实际测量成本后再决定是否需要 GPU 模拟；不引入新依赖。
4. 独立 OceanInteraction 管理水面局部射线、遮挡、速度、轨迹插值、静止阈值。鼠标按下/拖动、滚轮、相机惯性、离开水域或页面失焦时停止新注入，已有波纹继续求解。触屏继续专用于旋转/缩放。
5. 原型先运行于 water-lab，提供不透明 Wave Debug、低视角、参数与深度对照；验证后才连接正式场景。
6. 原面板增加 Interaction Strength / Ripple Propagation / Ripple Damping，保留 Auto/Manual、天气、预设和原布局。参数都有安全范围，天气不覆盖手动值。
7. 水下地形加强局部沙脊与深浅层次，岩石按新海床重新接地。评估厚度后优先保留原底座高度，避免改变道路建筑和整体构图。有限 Fresnel、吸收和高光近似，不上重型反射引擎。

## 边界和验收

只修改 ocean/water、独立实验页、海洋面板，以及必要的场景接线/生命周期。Rainy Konbini、道口状态机、轨道和站房不作为海洋实现改动对象。

验收包括：基础波与交互波实际几何位移、慢/快移动强度、离开/停止后的传播衰减、无拖动/缩放假注入、参数极值和天气隔离、水面/侧壁连续、海床岩石接地、资源回收。实际浏览器录屏与不透明调试截图证明动态效果。

此外沿铁路与过轨人行道检查：完整轨头可见，步行面下方有闭合路基，信号柱接地，过渡不悬空，不改变电车和栏杆扫掠。真实 iPad 不可用时明确模拟限制。
