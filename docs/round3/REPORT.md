## 水体技术选择

保留上一轮轻量自定义 Shader，未换成复杂水体系统。

| 方案                            | 表现与开销                                                                                                                      | 结论                                                    |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| MeshPhysicalMaterial + 动态法线 | 标准物理光照容易集成，但仍需协调顶点波、侧壁、法线贴图与环境反射；若使用实时反射需额外场景渲染                                  | 现有实验页继续保留用于比较；本轮不迁移                  |
| 轻量 Shader                     | 同一参数生成 JS/GLSL 波场；顶部和侧壁共享边界起伏、时间与昼夜；解析法线、有限 Fresnel、高光和深浅混色。无纹理或反射渲染目标依赖 | 正式采用，重点修正原几何/透明路径，而不是增加材质复杂度 |

水面和侧壁仍共享平均水位 .12、底界 -.78。最大振幅 .068，不产生大浪；顶面包围体扩展包含位移，避免裁剪误判。海床仍有轻微地形起伏，岩石接触真实海床。夜间降低高光，未采用金属水面、真实折射或复杂流体仿真。

采用 Three.js 内置 CylinderGeometry、Shape/ExtrudeGeometry 与分段网格实现枝干、双坡屋面及实体路基。没有下载或替换为 Poly Pizza / Kenney 等外部资产，不产生新的资源许可证义务。

## 修改文件

- `src/core/geometry.ts`：只修正错误树枝生成，增加住宅可选双坡屋顶；原树冠和普通平屋顶保留。
- `src/core/structures.ts`：端点枝干、Scene A 专用路缘护栏、闭合双坡屋壳和山墙。
- `src/scenes/SceneA.ts`：仅替换两处白护栏调用。
- `src/scenes/SceneB.ts`：仅集成相关屋顶、实体路基/边坡、海岸透明边界，以及直接受坡面影响的物体高度。
- `src/scenes/CoastalGround.ts`：共享路面/路缘/地形高度、封闭路基几何。
- `src/core/WeatherSystem.ts`：海岸涟漪跟随新的共享高度。
- `src/water/wave.ts`、`CoastalWater.ts`：连续波场、水体深度与面朝向、正交视线、色彩和贴地岩石。
- `tests/structures.test.ts`、`water.test.ts`：连接结构、屋壳闭合、接地、平交高度、侧壁共面与岩石贴地验证。
- `tests/browser/round3.spec.ts`：动态水体、多角度模型、窄屏检查与可选录屏。
- `tests/browser/round2.spec.ts`：仅将已变更的岩石数量断言更新为 8。
- `README.md`、本目录报告、审计数据、截图和录屏。

`src/ui/`、CSS、项目名称、相机模块、交互模块、道口状态机、依赖声明及锁文件均未改动。

## 验证结果

### 几何和构建

- `npm test`：**15 项通过**，没有跳过或禁用断言。
- 覆盖主枝/次枝端点连接、枝梢进入树冠、树模型面数、白护栏接地与末端支撑、双坡壳闭合、路基填实、轨面差 .02、边坡函数与实际三角面一致、水面/侧壁共用波场，以及岩石贴海床。
- 现有门扇扫掠、两侧道口栏杆和电车状态机测试也通过。
- `npm run build`：TypeScript 与生产构建通过。
- Vite 提示 Three.js 分包约 527 kB（gzip 134.9 kB），构建成功；没有新增 npm 包。
- 本地生产服务器实际打开双场景和两种水体实验页，WebGL 渲染有效，控制台错误为空。
- 格式检查与 `git diff --check` 通过。

### 浏览器与动态闪烁检查

运行了本轮相关的 **4 项浏览器用例并全部通过**：

1. 水体静止、慢转、快转、拉近、拉远，分别覆盖黄昏与夜晚，实际录屏。
2. 树木/护栏、屋顶/道路的默认、侧面和斜向视角，桌面与手机完整取景。
3. 原有双场景、天气、昼夜、相机、便利店交互、道口完整通行、重复点击锁定与资源生命周期回归。
4. 触屏点击、单指旋转、双指缩放回归。

路基面法线及贴合收尾后，几何用例做了定向复验并再次通过；没有为了本轮任务重跑无关的第二轮完整 UI 布局套件。

[水体动态录屏](water-motion.webm) 约 **36.7 秒**，覆盖上述黄昏/夜晚及镜头操作，检查中未观察到原先的整片跳色或明显闪烁，控制台无 Shader 异常；另外抽取录屏帧检查了水位、海床遮挡和颜色连续性。视频容器编码为 25 fps，实际软件 WebGL 渲染约 205 帧，不能把编码帧率当作硬件性能测量。

此次检查使用 Chromium + SwiftShader；**并非真实 iPad/Safari 硬件测试，不能保证所有 GPU/驱动上的表现**。静态图片只用于几何和色彩对照，动态录屏才是本轮闪烁检查的依据。

### 性能与生命周期

- 默认中雨海岸帧：约 **15,328 个三角形、235 次绘制**；修复前约 16,192 个三角形、220 次绘制。几何更合理且总三角形减少，实体路基和分叉带来少量绘制调用增加。
- 五轮场景切换后 geometry **232 → 232**、texture **3 → 3**，没有持续增长。
- 沿用原有 DPR、阴影、实例化雨/涟漪与释放逻辑；无新增反射帧缓冲或远程素材。
- 录屏仅为测试产物，位于 docs，不随 Vite 生产构建打包加载。正常浏览器测试不依赖录屏工具；设置 `RECORD_WATER_VIDEO=1` 可选择录制，需安装 Playwright FFmpeg 或配置可用的 FFmpeg 测试环境。
